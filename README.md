# Legalyti Competitor Content Radar

A small GitHub Pages prototype with three tabs:

1. **Competitor content** — seeded competitor guides and comparisons, with the search query used, observed page details, relevance, and a Legalyti response hypothesis.
2. **Competitor news** — company announcements and independent company coverage, separate from legal-topic content.
3. **Legalyti opportunities** — content ideas tied to competitor observations and Legalyti's public content/positioning, clearly marked as unapproved hypotheses.

## Current state

This is a **local prototype prepared for a future GitHub repository**. It has not been pushed to GitHub and is not connected to Legalyti systems, the CMS, Search Console, Semrush, HubSpot, or a production LLM. The initial snapshots were researched with TinyFish on 18 November 2026 for the United States.

- Three pilot query clusters: EB-1A evidence, EB-2 NIW proposed endeavor/evidence, and EB-1A versus EB-2 NIW.
- Nine competitor pages were seeded from search-discovery results and then fetched for visible metadata/content checks.
- Search-discovery order is **not** a verified Google ranking. Query volume and difficulty are unverified.
- Three competitor-news items are seeded from company announcements and a third-party company-growth article. Company statements remain attributed to their source.
- The three content recommendations are human-prepared pilot hypotheses, not generated by the automated LLM step and not approved content assignments.

## Step 1 — Review the pilot evidence

Before connecting automation, review:

- `data/query_clusters.csv` — the pilot searches and intent labels.
- `data/competitor_content.json` — page observations, discovery order, dates, and response hypotheses.
- `data/competitor_news.json` — dated company news items.
- `data/content_opportunities.json` — initial Legalyti ideas and review requirements.
- `data/positioning.md` and `data/content_inventory.csv` — the facts and existing Legalyti assets the ideation step can use.

Correct or remove any row that does not match the current target geography, audience, service coverage, or query focus.

## Step 2 — Preview the three-tab dashboard

From this folder, run a local static server:

```bash
python -m http.server 8000
```

Open `http://localhost:8000`. The page fetches its JSON files, so opening `index.html` directly with a `file://` URL will not load the dashboard data.

## Step 3 — Put it in a GitHub repository

Create a repository, upload these files, and enable GitHub Pages from the `main` branch root. The workflow is at `.github/workflows/refresh.yml`.

The weekly action checks the nine seeded public content pages and configured press listings. It respects a site's `robots.txt`, records only title/description/headings, dates, status, and a content fingerprint, and does not store whole competitor pages. A press-listing page may need selector or URL-pattern tuning after its first run.

## Step 4 — Enable controlled AI suggestions (optional)

The AI generation step runs only when someone manually dispatches the workflow with `run_ai` enabled. Configure repository secret `LLM_API_KEY` and repository variables `LLM_MODEL` and, if needed, `LLM_BASE_URL`. The default endpoint is an OpenAI-compatible chat-completions endpoint. A ChatGPT subscription does not itself provide an API key; API usage may incur separate charges.

`scripts/suggest.py` sends only public competitor metadata, the supplied content inventory, and the approved-fact starter file. It does not send client inquiries, legal conversations, documents, or case facts. It writes to `data/generated_opportunities.json`; it does not publish to the Legalyti site. Every output is labeled as an AI-generated hypothesis and must be reviewed.

## What this first version does not do

- It does not autonomously discover every new Google result or confirm rankings. Search discovery needs a SERP/search integration that GitHub Actions can actually call, or a refreshed manual seed list.
- It does not estimate search volume or difficulty without measured data.
- It does not publish content or make legal judgments.
- It does not scrape or automate the Legalyti app.
- The initial news listing sources are Manifest Law and Tukki. Add more validated competitor press/news sources in `data/news_sources.json`.

## Privacy, legal review, and output handling

- Keep user/legal inquiry data out of this repository and all model prompts.
- Treat competitor content as public-source evidence: link to the page, summarize it, and avoid copying substantial text.
- Attorneys review substantive immigration statements, case analysis, and jurisdiction-specific claims.
- Marketing reviews intent, differentiation, service fit, and CTA.
- The agent creates research and draft suggestions only. People choose what to create and publish.
